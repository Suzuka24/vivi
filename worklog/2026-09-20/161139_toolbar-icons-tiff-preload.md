# 工具栏图标与 TIFF 预加载调查

## 计划

- 目标：统一右侧八个工具图标的线条、简化图形并去掉组内分隔；查明用户更正后的指定 TIFF 预加载慢和远处帧未缓存的原因。
- 范围：工具栏 SVG/CSS；只读检查预加载和后端读取流程，不改变 TIFF 数据路径。
- 步骤：检查现有代码、读取远程文件头、测量单帧读取和渲染、修改图标、在远程 Cursor 验证。
- 验证：静态检查、现有测试、VSIX 打包和远程界面检查。

## 实施记录

- 用户起初给出 FITS 路径，随后更正为 `python_h_rl_allviews_iter1000/naomiv2_sum_rep00_density03_n04.tif`。初次 FITS 调查不再用于结论。
- TIFF 元数据：形状 `(101, 795, 795)`，`float32`，无压缩，101 页，每页单 strip，文件约 244 MiB，可 `memmap`。
- 远程 Python 后端实测：打开文件约 0.012 秒；第 0、50、100 帧完整读取分别约 0.036、0.0001、低于 0.0001 秒；含自动百分位数和 Base64 编码的 `render` 分别约 0.023、0.019、0.014 秒。每帧 `raw` 响应 3,370,800 个 Base64 字符，101 帧合计约 340 MB。
- 当前 `preloadFrameOrder` 对 101 帧返回全部 101 帧，`preloadFrames` 串行请求。默认 768 MiB 缓存上限大于 101 帧约 244 MiB 的 float32 预览，因此不会主动阻止全量预加载；远处帧长时间未就绪是传输队列尚未完成或被交互打断后重启。
- 一次 10 MiB SSH 传输耗时 5.91 秒，粗略吞吐约 1.7 MiB/s；340 MB 数据在该速度下需数分钟。该通道测试与 Cursor Webview 消息通道并不等价，单帧端到端耗时尚未独立计量。
- 将八个 SVG 图标简化为更少路径与刻线；保持图标外框尺寸，按与左侧图标相同的可见线宽调整 SVG stroke；去掉八个图标之间的竖线。

## 总结

- 性能结论：这份 TIFF 的慢主要不是磁盘读取或解码，而是每帧约 3.37 MB 的 Base64 数据需要通过远程连接逐帧送到 Webview。现有策略会尝试加载全部 101 帧；这一点与用户提出的“不希望全部加载”不符。更精确的耗时分解需要端到端打点。
- 本轮仅修改图标，不修改预加载算法和显示数据精度，待与用户讨论。优先建议仅预取附近少量完整帧，当前帧优先；随机跳转时按需加载。
- `npm run check`、12 项 `npm test`、`npm run package`、`git diff --check` 通过。0.6.13 已安装到本地和远程 Cursor，在独立远程窗口用 2D TIFF 验证图标分组、线宽和简化样式。
