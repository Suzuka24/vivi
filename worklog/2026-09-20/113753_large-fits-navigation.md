# 大型 FITS 导航与 Layout 滚动

## 计划

- 目标：定位指定 FITS 加载缓慢的原因；让 slice 左右按钮长按按 FPS 连续切换；让 Layout 多 Frame 列表独立纵向滚动。
- 范围：预览预载策略、Viewer 按钮事件和 Layout 样式，不修改源 FITS。
- 步骤：测量远程文件与单帧读取；限制超大 stack 的后台预载窗口；实现按钮长按；修复 Frame 列表的 flex 滚动；远程 Cursor 验证。
- 验证：直接相关的 Node/Python 测试、远程真实 FITS 的首帧与缓存状态、多个 Frame 的列表滚动及按钮交互。

## 实施记录

- 远程文件为 2,202,045,120 字节，FITS 数据形状 `(4, 1050, 256, 256)`，64 位浮点，共 4200 个二维 slice。远程后端打开约 0.08 秒，单张预览读取及生成约 0.002–0.006 秒；每张预览经 base64 传输约 350 KB。慢的主要原因是旧版尝试后台预载数千张预览，带来持续 SSH 传输和缓存占用。
- 将 512 张以上的 stack 的后台预载限制在当前 slice 周围最多 48 张，并增加约 64 MiB 的单次预载预算；较小 stack 继续完整预载。
- 为显示区的 slice 左右按钮实现按下即切换、按住 350 毫秒后按 FPS 连续切换、松开停止，并兼容辅助功能和键盘触发的 click。
- 修复 Layout 控件的 flex 高度与 Frame 列表滚动设置，使溢出的 Frame 在自己的区域纵向滚动。
- 构建并安装 `0.6.7` VSIX 到远程 Cursor。在独立远程窗口打开指定 FITS，确认显示 `48 nearby cached`；单击下一张切换到 slice 2。打开 9 个 Frame 后，确认 Layout 可滚动并选中第 9 个。独立测试窗口已关闭，远程临时符号链接与 VSIX 安装文件已删除。

## 总结

- 完成指定 FITS 的慢加载根因排查与后台预载限制、长按切帧及 Layout 多 Frame 滚动。
- `npm run check`、11 个 Node 测试、25 个 Python 测试和 VSIX 打包通过；远程 Cursor 进行了真实 FITS 与 9 Frame 的 UI 验证。
- 长按持续切换的计时逻辑已经实现，但本次 UI 自动化只验证了单击；需在真实鼠标长按场景继续观察。对于超出邻近缓存的远处 slice，仍需按需从远程读取。
