# 显示参数改变后主动重建 stack 画面

## 计划

- 目标：B&C 等显示参数改变后立即更新已缓存切片的可绘制画面，切片切换不再闪空白。
- 范围：检查手动、Auto/Reset、LUT、反相、阈值、同步 frame 与原位翻转/旋转路径；保持已有 raw 缓存和源数据行为。
- 步骤：修正异步着色和画面替换方式；主动重绘缓存切片；补齐原位变换对已缓存画面的更新；验证本地测试和远程 Cursor 中的 stack 操作。
- 验证：静态检查、相关测试、打包；在 hyh-batchcom2 Cursor 对 101 帧 TIFF 调 B&C 后跨帧切换，确认画面持续可见。

## 实施记录

- 着色改为在新 canvas 完成后一次性替换，避免重设原 canvas 尺寸时清空当前画面。
- 显示参数更改时主动遍历该 frame 已缓存的切片、overview 和 tile 画面，从当前切片附近开始更新；新到达的预加载切片用最新参数再着色后入缓存。
- 连续调整使用版本号阻止旧的异步着色结果覆盖新画面。Auto/Reset 路径也纳入主动更新。
- 原位翻转和 90° 旋转同步变换缓存的 canvas，避免 raw 仍标记已缓存而 image 被置空。
- 后台到达的 overview 在进入缓存前重新应用当前显示参数；当前切片暂未就绪时继续显示上一张已绘制画面。

## 总结

- 已修复 B&C、Auto/Reset、stretch、LUT、反相、阈值和同步 Frame 的主动重绘路径；切片切换不再通过清空旧 canvas 来重绘，原位翻转和直角旋转保留可绘制对象。
- `npm run check`、`npm test`（21 项）、`npm run package`、`git diff --check` 通过。新增测试覆盖原画面直到替换完成、各缓存切片主动重绘，以及变换后 canvas 保留。
- hyh-batchcom2 Cursor 中目标 101 帧 TIFF 达到 101/101 ready；调整 Minimum 后直接跳到第 90 帧，切片和 Curve 数值正常且无错误提示。本机、hyh-batchcom2、ssk-CAST 已安装 0.6.23；三处 `viewer.js` SHA-256 一致。
- 最终版重载远程窗口时，打开路径命令的输入框尚未出现，自动输入误落到一个已有未保存修改的 Python 编辑器；已连续撤销这次输入和回车，确认该行恢复为原先代码，未保存或覆盖用户文件。
- 限制：远程界面检查确认状态和操作无错误；本次未获得逐帧屏幕录像来量化短时闪烁。对尚未从服务器读取的切片，仍需等待数据到达；等待期间保留已有画面。
