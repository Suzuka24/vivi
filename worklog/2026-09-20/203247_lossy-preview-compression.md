# 计划

目标：对目标 101 帧 float32 TIFF 比较 zfp、SZ3、12/16 位分块量化等方案的体积、误差与耗时，并实现可配置的预览有损传输。

范围：只改变远程到 webview 的预览像素传输，不改写源文件或服务端分析；有损开关、源文件大小阈值、方法选择与原有无损开关独立。所有正式可选方法必须可在 webview 解码。

关键步骤：在远程 Python 环境读取代表性帧做同条件基准；确定默认方案；添加编码、解码、设置及双阶段处理；验证字节协议、误差、阈值和组合开关；更新文档、远程 Cursor 安装及仓库。

验证：Python/JS 传输测试、端到端远程 Cursor 预览、原始分析数值不变；检查无损、仅有损、两者组合、均关闭四种模式；清除 `/tmp` 的测试文件。

# 实施记录

- 目标源文件大小 255,356,172 B；远程 venv 初始没有 zfpy、pysz，已为基准安装其官方 Python wheel，并清除 wheel 临时文件。
- 读取全部 101 帧（每帧 795×795 float32，2,528,100 B），对各算法做远程 Python 往返编码。`wire` 是有损编码结果与 zlib level 1 再压缩结果的较小者，模拟可选无损阶段；未计 JSON 封包和 SSH 传输耗时。误差按解码结果与源帧原始像素比较。PSNR 是逐帧相对本帧动态范围计算后取平均。

原始 101 帧共 243.54 MiB。压缩率与误差是特定图像的结果，不保证适用于其他数据。SZ3 在本数据上压缩效果最好，但目前缺少可在 vivi Webview 内直接使用和验证的 JavaScript/WASM 解码器，故只纳入基准，不暴露为无法端到端工作的设置。ZFP 在可实际跨 Python/浏览器互通的算法中有良好的误差和体积平衡，因此设为默认方法；有损总开关仍默认关闭。基准完整逐帧数据见同名前缀 CSV，脚本见同名前缀 Python 文件。

可选无损阶段在 ZFP 1e-4 后平均另需 14.6 ms/帧，在 float16 后平均 27.6 ms/帧，在分块 16 位后平均 44.0 ms/帧；若压缩后变大，生产路径会保留编码字节。基准表中 ZFP 1e-4 的 Python 解码平均 10.0 ms/帧，SZ3 1e-5 为 10.8 ms/帧；实际 Webview 的 WASM 解码耗时及 SSH 吞吐未包含在本基准中。分块量化使用 64×64 局部最小最大值，8 位虽比 ZFP 更小但误差大得多；16 位误差较低，传输体积却约为 ZFP 的三倍。float16 有低动态范围限制，bfloat16 在此数据上的误差明显大于 ZFP。

## 总结

- 新增 `vivi.lossyCompression`、`vivi.lossyMinFileMiB`、`vivi.lossyMethod`、`vivi.lossyTolerance`；先有损编码，再由原 `vivi.losslessCompression` 开关独立决定是否做可逆压缩。默认关有损、开无损；源文件和服务端分析不变。整数或含 NaN/Inf 的帧走原始 dtype 字节传输。
- 在 hyh-batchcom2 的远程 Cursor 0.6.22 打开目标 TIFF，启用 ZFP 后画面正常，101/101 帧预载完成；远程后端针对六种可选方法与无损开关两种状态共 12 种组合逐一返回有效数据。临时测试设置已撤回。
- 本地 `npm run check`、18 项 Node 测试、33 项 Python 测试通过；其中 Python 产出的有损字节在 JavaScript 中解码并比较误差，覆盖奇数像素的 12 位打包。打包 VSIX 成功；本地和两台远端 Cursor 均已安装 0.6.22。
- 剩余限制：SZ3 暂仅用于基准，不提供设置项；有损预览的画面像素值是近似值，精确读数应关闭有损；本次没有测实际 SSH 端到端耗时。已清理此次创建的本地与远端 `/tmp` 测试文件。
