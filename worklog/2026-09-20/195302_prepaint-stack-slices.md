# Stack 预加载同步生成显示画面

## 计划

- 目标：已完整预加载的 stack 首次播放远处切片时不再闪白，也不因重复着色而延迟切换。
- 范围：预加载构建每帧的 canvas 显示画面；显示参数未变化时复用画面，变化时仍根据原始像素重着色。
- 验证：运行语法检查和直接相关测试；在远程 Cursor 验证 ready 计数与首次播放；打包并安装到本地及两个远程 Cursor。

## 实施记录

- 预加载改为在缓存每帧前完成 `recolorEntry`，使 ready 计数反映可绘制的帧。
- 缓存着色参数签名；切片切换时参数一致就直接复用画面，B&C/LUT 等改变后仍重新着色。

## 总结

- 已实现预加载时构建每帧显示画面；参数不变时，切帧复用已绘制的 canvas，避免首轮播放的空白闪烁和重复像素转换。
- 本地 `npm run check`、`npm test`（15 项）、`npm run package` 和 `git diff --check` 通过。
- 远程 hyh-batchcom2 Cursor 使用 101 帧 TIFF 验证：101/101 ready 后首次直接跳至第 100 帧可显示图像，随后播放切片持续前进。0.6.19 已安装到本地和 hyh-batchcom2、ssk-CAST 两台远程 Cursor。
- 代价：预加载需要为每帧增加着色计算和 canvas 内存；未完成预加载就播放时，尚未就绪的帧仍需等待读取与着色。
